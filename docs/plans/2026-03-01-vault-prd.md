# Vault — Product Requirements Document

**Date:** 2026-03-01
**Version:** 1.0
**Status:** Approved

---

## 1. Product Overview

### 1.1 What is Vault?

Vault is a local-first platform that transforms YouTube podcast episodes into a searchable, structured knowledge base. It downloads podcast audio, identifies who said what (speaker diarization), and extracts actionable insights — frameworks, quotes, stories, business ideas, book recommendations — all without sending data to cloud services.

### 1.2 Problem Statement

Podcast episodes contain dense, valuable knowledge but it's locked in long audio/video format. Listeners forget key insights, can't search across episodes, and have no way to browse by topic. Existing tools require cloud APIs (expensive, privacy concerns) or manual effort.

### 1.3 Target Users

- **Primary:** Content creators / podcast fans who want to build a searchable knowledge vault from their favorite channels (starting with Diary of a CEO)
- **Secondary:** Researchers, entrepreneurs, students who want to extract and organize structured knowledge from long-form content

### 1.4 Inspiration

[MFM Vault](https://www.mfmvault.com/) — a knowledge extraction platform for the "My First Million" podcast. Vault aims to replicate this experience for any YouTube podcast channel, running entirely locally.

## 2. Goals & Success Criteria

### 2.1 Goals

| Goal | Metric |
|------|--------|
| Process any YouTube podcast episode locally | Download → diarize → extract in < 30 min for a 1-hour episode |
| Accurate speaker identification | Diarization Error Rate (DER) < 15% on DOAC episodes |
| High-quality insight extraction | > 80% of extracted insights rated "useful" by user review |
| Multi-channel support | Add any YouTube channel with per-channel prompt customization |
| Zero cloud dependency | All processing (STT, diarization, LLM) runs on local hardware |

### 2.2 Non-Goals (v1)

- Real-time transcription / live streaming
- Mobile app
- Multi-user / authentication
- Automated scheduling / continuous ingestion
- Non-English language support

## 3. User Stories

### 3.1 Channel Management

- **US-1:** As a user, I can add a YouTube channel by URL so I can start processing its episodes.
- **US-2:** As a user, I can view a list of all added channels with episode counts.
- **US-3:** As a user, I can configure channel-specific settings (default intro skip, custom prompts).

### 3.2 Episode Ingestion

- **US-4:** As a user, I can add a single YouTube video URL to be processed.
- **US-5:** As a user, I can bulk-add all videos from a channel (with an optional limit).
- **US-6:** As a user, I can see the processing status of each episode (downloading, preprocessing, diarizing, reviewing, extracting, done).

### 3.3 Diarization Pipeline

- **US-7:** As a user, I can trigger diarization on a downloaded episode using either PyAnnote or whisper-diarization.
- **US-8:** As a user, I can view the diarized transcript with speaker labels and timestamps.
- **US-9:** As a user, I can compare side-by-side results from both diarizers to decide which is better.
- **US-10:** As a user, I can edit speaker names (e.g., "Speaker 0" → "Steven Bartlett").
- **US-11:** As a user, I can correct misattributed segments by reassigning speakers.
- **US-12:** As a user, I can tag segments as intro/ad/subscribe/content.
- **US-13:** As a user, I can re-run diarization on a specific time range.

### 3.4 Intro Detection

- **US-14:** As a user, I can see the auto-detected intro boundary for a DOAC episode.
- **US-15:** As a user, I can manually adjust the intro boundary timestamp before diarization.
- **US-16:** As a user, I can set a default intro skip per channel that applies to new episodes.

### 3.5 Knowledge Extraction

- **US-17:** As a user, I can trigger LLM extraction on an approved transcript to get structured insights.
- **US-18:** As a user, I can configure which LLM model to use per extraction task (smaller for titles, larger for content).
- **US-19:** As a user, I can view extracted insights organized by type: frameworks, quotes, stories, opinions, business ideas, products, books.
- **US-20:** As a user, I can re-run extraction on a specific episode if the results aren't good.

### 3.6 Vault UI (Browse & Search)

- **US-21:** As a user, I can view an episode page similar to MFM Vault with: embedded YouTube player, tabbed insights (Summary, Quotes, Stories, Frameworks, etc.), and a full transcript.
- **US-22:** As a user, I can click any word/sentence in the transcript to jump to that moment in the YouTube video.
- **US-23:** As a user, I can search across all transcripts and insights with full-text search.
- **US-24:** As a user, I can browse all insights of a given type across episodes (e.g., all frameworks from all DOAC episodes).
- **US-25:** As a user, I can view guest profiles with their episodes and extracted insights.

### 3.7 Pipeline Dashboard

- **US-26:** As a user, I can see a dashboard with the status of all pipeline jobs (pending, running, completed, failed).
- **US-27:** As a user, I can see progress percentage for running jobs.
- **US-28:** As a user, I can see error details for failed jobs and retry them.
- **US-29:** As a user, I can configure LM Studio connection settings (URL, model selection).

## 4. Functional Requirements

### 4.1 Download Pipeline

| Req | Description |
|-----|-------------|
| FR-1 | Accept YouTube video URLs (watch, short, bare ID formats) |
| FR-2 | Accept YouTube channel URLs and list all videos |
| FR-3 | Download audio as WAV using yt-dlp |
| FR-4 | Extract metadata: title, description, duration, upload date, thumbnail |
| FR-5 | Skip already-downloaded episodes |
| FR-6 | Store audio at `data/audio/{channel_slug}/{youtube_id}.wav` |

### 4.2 Preprocessing

| Req | Description |
|-----|-------------|
| FR-7 | Convert audio to 16kHz mono WAV via ffmpeg |
| FR-8 | Auto-detect intro end using RMS energy analysis |
| FR-9 | Preserve full audio (no cutting) |
| FR-10 | Store intro_end_at timestamp in episode record |

### 4.3 Diarization

| Req | Description |
|-----|-------------|
| FR-11 | Support two diarization backends: whisper-diarization and PyAnnote |
| FR-12 | Produce word-level or segment-level timestamped transcript |
| FR-13 | Assign speaker labels to each segment |
| FR-14 | Store diarization benchmarks (processing time, optional WER/DER) |
| FR-15 | Allow user to select diarizer per episode |

### 4.4 Segment Management

| Req | Description |
|-----|-------------|
| FR-16 | Store segments with: start_time, end_time, text, speaker, tag |
| FR-17 | Support segment tags: intro, ad, subscribe, content |
| FR-18 | Allow editing speaker names globally (rename across all segments) |
| FR-19 | Allow reassigning individual segment speakers |
| FR-20 | Auto-tag segments before intro_end_at as "intro" |

### 4.5 Extraction

| Req | Description |
|-----|-------------|
| FR-21 | Connect to LM Studio via OpenAI-compatible API |
| FR-22 | Split transcript into overlapping chunks for extraction |
| FR-23 | Extract: frameworks, quotes, stories, opinions, business ideas, products, books |
| FR-24 | Generate titles for each insight (active voice, specific) |
| FR-25 | Map insights to start/end timestamps in the transcript |
| FR-26 | Generate structured markdown for frameworks |
| FR-27 | Support channel-specific prompt customization |
| FR-28 | Allow configurable model per task type |

### 4.6 Search

| Req | Description |
|-----|-------------|
| FR-29 | Full-text search across all transcripts |
| FR-30 | Filter search by channel, episode, insight type |
| FR-31 | Return results with surrounding context and timestamps |

### 6.2 Pipeline Stages

```
[Download] → [Preprocess] → [Diarize] → [Review] → [Extract] → [Done]
  yt-dlp       ffmpeg        Whisper+     Dashboard    LLM        API
               librosa       NeMo/PyAnn   (manual)    (LMStudio)
```

| Audio | ffmpeg, yt-dlp, librosa |

## 7. Data Model

### Entities

- **Channel** — YouTube channel (name, slug, youtube_id, default intro skip, config)
- **Episode** — Single video (title, youtube_id, duration, audio_path, status, intro_end_at)
- **Segment** — Transcript segment (start_time, end_time, text, speaker, tag)
- **Insight** — Extracted knowledge (type, title, content, timestamps, speaker)
- **Guest** — Person appearing in episodes (name, role, company, bio)
- **Job** — Pipeline task (stage, status, progress, error)
- **Benchmark** — Diarization comparison data (diarizer, processing time, accuracy)

### Relationships

- Channel → many Episodes
- Episode → many Segments
- Episode → many Insights
- Episode → many Jobs
- Episode → many Benchmarks
- Episode ↔ many Guests (junction table)

## 9. Risks & Mitigations

| Risk | Impact | Mitigation |
|------|--------|-----------|
| Diarization accuracy on DOAC intros | Incorrect speaker labels in intro section | Auto-tag intro segments; user can manually adjust |
| Apple Silicon compatibility for NeMo | whisper-diarization may not run on MPS | Test both backends; PyAnnote has native MPS support |
| LM Studio model quality for extraction | Poor insight extraction with small models | Configurable model per task; benchmark different sizes |
| yt-dlp YouTube blocking | Downloads may fail due to YouTube rate limiting | Add retry logic, respect rate limits, use cookies if needed |
| Large audio files filling disk | 1-hour podcast WAV = ~350MB | Compress to FLAC after processing; add storage warnings |
